**2) 时间显示到年月（前端）**

```js
function fmtYm(v) {
  const m = String(v).match(/(\d{4})\D*(\d{1,2})?/)
  return m[2] ? `${m[1]} 年 ${parseInt(m[2],10)} 月` : `${m[1]} 年`
}
```

**4) 关键：校准记录保留具体日子**
后端 `PUT /{id}/card-data` 加 `_keep_day()`：
```python
def _keep_day(new_val, old_val):
    # 卡片只传「年-月」，但校准记录要留完整日期 → 沿用原来的「日」
    if new_val and len(new_val) <= 7 and old_val:
        m = re.match(r"^(\d{4}-\d{2})-(\d{2})", str(old_val).strip())
        if m: return f"{new_val}-{m.group(2)}"
    return new_val
```
→ 卡片上显示「2026 年 8 月」，库里 `calibration_date` 仍是 `2026-08-15` ✓

## 【真凶2】CrudTable refresh 读 computed props 读到旧值 → 筛选参数丢失（2026-10-02 22:40）

**抓包定位**（`outputs/wjx/probe_group_filter.cjs`，Playwright 监听 `request`）：
- 首次进入：`page=1&page_size=20&status=在用&q=` ← 正确（无 group_code）
- **选择「血库」后：根本没有发出新请求**，列表纹丝不动

**根因**：`CrudTable.vue::refresh()` 读 `props.extraParams`，而 `extraParams` 是父组件的 **computed**。父组件 `@change` 里改 `groupFilter` 后**立刻同步调用** `crud.refresh()`，此时 Vue 尚未完成 props 更新，`props.extraParams` 仍是**旧值**（`{status:'在用'}`）→ 请求发出去了但没带 `group_code`。
**修法**（`CrudTable.vue`，commit `2d3e81b6`，build mark `fix-crudtable-nexttick-2026-10-02`）：
```js
async function refresh() {
  loading.value = true
  try {
    await nextTick()          // ← 关键：等 props 更新完再读
    const params = { page: page.value, page_size: pageSize.value, ...props.extraParams, q: q.value }
```
并在 `import { ref, onMounted } from 'vue'` 补上 `nextTick`。

### 排查方法沉淀
1. **"显示了但行为不对"** → 不要再看代码，直接 **Playwright 抓 request**，一眼看出"请求根本没发"还是"发了但参数不对"还是"后端返回错"。本次正是靠抓包确认"没发请求"，才排除了后端和传参逻辑，直指时序问题。
2. `el-select @change` + computed props + 子组件手动 refresh 的组合 = 经典时序坑；父组件改值后调子组件方法，**必须 `await nextTick()`**（或让 CrudTable 自己 `watch(() => props.extraParams, refresh)`）。

## 【真凶3】非生免组菜单白名单裁剪 → 血库组看不到「性能验证」入口（2026-10-02 23:20）
用户反馈"性能验证各组独立，我没看到呀"。后端隔离确实在（三个 router 的 `group_scoped=True` 都在），但**入口被裁掉了**。
**Playwright 探测实证**（`outputs/wjx/probe_verification.cjs`）：用贾国伟登录后
- 侧边栏只有 13 项，**没有「性能验证」「项目质量要求」「仪器关联管理」**
- 手动访问 `/verification` → **被重定向回 `/dashboard`**（路由匹配不上/被裁）
- 工作台全是 0（项目 0、仪器 0 台）—— 血库组本来就没数据，属正常
**根因**：`AppLayout.vue::menus` 里有一段「专业组裁剪」：
```js
// 非生免组只保留白名单菜单
if ((auth.groupCode || 'sm') !== 'sm') {
  return visible.filter((m) => OTHER_GROUP_PATHS.has(m.path))
}
```
`OTHER_GROUP_PATHS` 原来只有 12 项（工作台/项目/文件/仪器 + 试剂系列），**不含 `/verification`** → 隔离做在数据层，但**菜单层把入口藏了**，所以"看不到"。
**修法**：白名单补上 5 个路径（commit `776ca560`，build mark `open-verification-menu-2026-10-02`）：
```js
'/verification', '/quality-requirements',
'/instrument-families', '/eqa-associations', '/post-instrument-map',
```
- `/verification` → 性能验证（5 个页签：记录/档案/报告归档/不确定度评定/不确定度汇总，**已全部按组隔离**）
- `/quality-requirements` → 项目质量要求（全科共享标准库）
- `/instrument-families`、`/eqa-associations`、`/post-instrument-map` → 仪器关联类（各组维护自己的映射）

### 教训（架构级，必须记住）
1. **"给某组开放某模块"要做两处**：① 数据层 `group_scoped`/权限 ② **菜单层 `OTHER_GROUP_PATHS` 白名单**。只做 ① = 功能做好了但没人看得见。
2. `AppLayout.vue` 的 `OTHER_GROUP_PATHS` 是**非生免组的总开关**——以后新增面向其他专业组的模块，**必须同步加进这个 Set**，否则该组用户根本看不到入口。
3. 验证"某组能不能看到某模块"要用 Playwright **登录该组账号 + 抓侧边栏菜单文本 + 看请求**，不要只 curl API（API 通 ≠ 菜单有入口）。

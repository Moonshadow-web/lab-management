# 2026-08-18 性能验证报告 5 项问题修复

## 1) 下载失败
- 根因：`storage.get_path()` 在容器重启本地磁盘清空后找不到文件→404
- 修：verification_reports.py 和 report_archives.py 的 download 端点改用 `persist_get_path()`（本地+COS 双写兜底，容器重启仍可下载）
- 实测 verification-reports/1 download=200 (220KB)

## 2) 上传的无法在性能验证记录里自动解析生成
- 老数据 #1 ALT 上传时还没接自动解析逻辑（ref_report_id=None）
- 修：upload_archive 端点已能自动解析（之前已部署）+ 新增 `POST /report-archives/{aid}/reparse` 回填老数据
- 前端归档页加"重新解析"按钮（"未解析"状态显示橙色钮，"已关联"显示"查看记录"钮）

## 3) CV 分低值/高值（原版格式）
- 原版：precision1（批内CV）= "低值X% 高值Y%"
- 原版：precision2（实验室内CV）= "低值X% 高值Y%"
- 旧算法只算总体 CV（混 L1/L2）
- 新算法按水平分别算：
  - 批内CV：每天 3 次重复的 SD/Mean，再跨天平均
  - 实验室内CV：所有数据 SD/Mean
  - 输出："低值0.36% 高值0.55%"
- 兼容 wizard `rows` 字段和 parser `days` 字段
- 重生成时强制重算（检测到"CV X%"旧格式即覆盖）

## 4) 抗干扰/分析特异性细到每个干扰物（原版格式）
- 旧：笼统的"胆红素/甘油三酯/血红蛋白干扰能力符合厂家声明"
- 新：从 data.specificity.items 拼出 "胆红素 <=1000umol/L  实测<=允许偏倚；甘油三酯 <=1500mg/dL  实测<=允许偏倚；血红蛋白 <=500mg/dL  实测<=允许偏倚"
- 重生成时检测旧格式"符合厂家声明"自动重算

## 5) 验证内容/结果空修复
- 根因：vrf_parser._read_summary 中 B/C/D 三列都空时漏掉该行 → verify_items 为空 → R14 内容空
- 修：增加 `_content_from_row()` 按行号硬推导 + 触发判定条件放宽（content/result/conclusion 任一非空即收录）
- key 用英文 subKey（precision1/2/reportable1/2）避免被原 verify_items 判断逻辑搞丢多行

## 6) 项目验证档案（新页面）
- 需求："对项目验证内容/结果单独建表，能快速按项目查询"
- 实现：
  - 后端 `GET /api/v1/project-verification-archive/list-by-project`：按 project_name 聚合，每项目一个对象，含 latest_id/date/items/all_records
  - 用纯 APIRouter（不 make_router）避开 `{item_id}` 路由抢匹配
  - 前端新建 `ProjectVerificationArchive.vue`：按项目分组的列表 + 展开看每次验证明细 + 下载/查看按钮
  - tab 已加到 VerificationList 中："项目验证档案"
- API 路径用独立 prefix `/project-verification-archive/...` 避免与 `/verification-reports/{item_id}` 冲突

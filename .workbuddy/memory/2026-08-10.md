## 15189 接收新版本后跳转到别的界面（已修复上线）
用户反馈：点"接收生成版本"确认后跳到别的界面（被踢到登录页再落到工作台），要求接收后留在 15189 页面。
- **第一版尝试失败**：仅在 ReviewTab.submitReceive 加 try-catch + 恢复展开行。原因：代码里无任何 router.push，唯一导航是 `request.js` 拦截器的 `gotoLogin()`（401→`router.push('/login')` 且先于 reject 执行），try-catch 拦不住。
- **根因链**：access token 30min 过期 → receiveRevision(或 loadAll 子调用) 401 → 拦截器用 refresh token 续期，若 refresh 也失败 → `clearAuth()` + `gotoLogin('/login')` → `Login.vue` 登录成功硬编码 `router.push('/dashboard')` → 落到工作台而非原 15189 页。
- **正确修法（3 文件）**：
  1. `utils/request.js` `gotoLogin()`：记住 `router.currentRoute.value.fullPath`，以 `?redirect=` 带到登录页（已在 /login 则不重复跳防循环）。
  2. `views/Login.vue`：登录成功后 `router.push(route.query.redirect || '/dashboard')`（引入 useRoute）。
  3. `router/index.js` `beforeEach`：`to.path==='/login' && auth.isLoggedIn` 时 `next(to.query.redirect || '/dashboard')`。
- **验证**：curl 实测 refresh 端点可用(200)、假 token 返回 401；线上 `Login-D99a0Tfu.js` 含 redirect、`index-C_-lrpv8.js` 含 4 处 redirect、引用新 `Iso15189Hub-CBwT8GHm.js`。
- 提交 `dc0d069`，build 标记 `login-redirect-return-2026-08-10`，已 deploy 生效。
- **复用结论**：前端"操作后跳登录/跳走"类问题，先用 grep 确认有无 router.push；若无，必是拦截器 401→gotoLogin。修法不是 try-catch，而是让登录后回跳原页面（redirect 参数）。token 30min access + 7d refresh 是项目铁律。

# 2026-08-04 工作记录

## 浏览器进不去(白屏)根因与修复
- 现象：手机能进、PC 浏览器进不去。后端/资源均 200 健康。
- 根因：`backend/app/main.py` 的 `AssetCacheMiddleware` 仅给 `/assets/` 设 `immutable` 永久缓存，
  SPA 入口 `index.html`(根路径/SPA fallback)无 `Cache-Control` 头 → 浏览器按 `Last-Modified`
  启发式强缓存旧版入口页；新构建删除了旧主 JS chunk → 旧 index.html 引用 404 → 白屏。
- 修复：中间件扩展——对 `text/html`(即 index.html)加 `Cache-Control: no-cache`，
  强制每次向服务端校验；`/assets/` 仍 `immutable` 长期缓存。
- 部署：`_BUILD_MARK=spa-nocache-header-2026-08-04`（远端 tip `492983f`），已上线验证
  `index.html` 返回 `cache-control: no-cache`，入口 JS `index-Bbu3o-h3.js` 200。
- 经验：以后每次前端部署，用户 PC 端即便不硬刷也不会再卡旧版（no-cache 兜底）。
- 临时救急：用户旧浏览器仍缓存旧页，硬刷新(Ctrl+Shift+R)即可立即进。
- 验证：用户实测 Chrome 硬刷后可进、Edge 更新后旧缓存进不去、Edge 无痕窗口可进 → 确认纯客户端缓存问题，
  服务端健康（index.html no-cache、入口 JS 1.26MB、登录200）。当前构建未注册 Service Worker（/sw.js 等仅为 SPA fallback 空壳）。
- 给用户的最终指引：Edge 普通窗口 F12→Application→Clear site data，或 edge://settings/clearBrowserData 清"缓存的图像和文件"，或 Ctrl+Shift+R。
- 深入排查(用户"硬刷/清缓存/加?v=2参数/关扩展都试过仍白屏")：已排除普通磁盘缓存、Service Worker、扩展拦截。下一步指向 Edge 进程级/代理层缓存——
  ①任务管理器结束所有 Microsoft Edge 进程再重开(绕开"启动增强/后台进程缓存")；②edge://net-internals/#httpCache 点 Clear cache(清代理层缓存)；
  ③关"启动增强"edge://settings/system + 关"节省数据/代理加速"。若仍白屏，请在普通窗口 F12→Console 执行
  `document.querySelector('script[src]')?.src` 与 `performance.getEntriesByType('resource').filter(r=>r.name.endsWith('.js')).map(r=>r.name+' '+r.responseStatus)`
  把结果发我，可区分"旧HTML缓存"vs"JS被拦截/执行报错"。
- 最终验证：用户**新建 Edge 配置文件后能进系统** → 根因确认为旧 Profile 的顽固缓存/状态损坏（与服务器无关，服务端已确认健康）。
  代价：新 Profile 独立密码库，旧密码"看似丢失"；但旧 Profile 并未删除，可从旧 Profile 导出/导入密码或切回抄录。
  结论：以后遇"某浏览器特定窗口白屏、无痕/新Profile能进"类问题，直接建议新建 Profile 或修复 Profile，不必死磕清缓存/杀进程。

- 现象：刚部署完（约 7 分钟前标记才生效）用户测 Edge 又白屏。

- 注意：git-bash 下 `curl -w size_download` 对本站点大文件报 0（统计 bug），须用 Python urllib 核实真实字节；勿据此误判 JS 为空。
- 结论：本次白屏时间点恰好贴合刚完成的部署，属 CloudBase Run 滚动发布过渡期（旧/新容器短暂混部，Edge 若拿到旧页引用、其 JS 已在新容器被删→个别资源 404→白屏），**临时现象**。
- 处置建议（优先级）：①Edge 地址栏 Ctrl+Shift+R 硬刷新一次即恢复；②若仍白，F12→Application→Storage→Clear site data（仅清本站点缓存，不丢密码）再刷；③不必再让用户重建 Profile/折腾浏览器。下次"部署后不久报白屏"默认先硬刷，不急于排查服务端。
- **用户反馈硬刷+清站点缓存均无效**；进一步确认 **Chrome 能进、仅 Edge 白屏** → 彻底排除服务端/CDN/部署，问题 100% 在 Edge 客户端。
- **根因推断（Edge 反复白屏）**：Edge 登录 Microsoft 账号并开启"同步"，新建 Profile 后把旧 Profile 损坏的缓存/设置同步回来，导致"新建 Profile 能进、过阵子又白"的循环；叠加 Edge"启动增强"后台进程持有旧资源、普通清缓存清不掉。非系统问题。
- **一劳永逸方案**：新建一个**不登录微软账号/关闭同步**的专用 Profile 访问本系统（可先 `edge://settings/passwords` 导出密码→新 Profile 导入，避免丢密码）；专用 Profile 切勿开同步。勿再耗在服务端排查。

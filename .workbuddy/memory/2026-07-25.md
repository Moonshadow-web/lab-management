## R-4s 改为 SD 归一化跨水平比较（已部署）

### 问题
用户反馈 e601「甲肝 IgM 抗体」月结把水平2（2.32/2.56/2.44/2.49）整月判 R-4s 失控。根因：旧 R-4s 用**原始测值差 > 4×max(sd)**，而水平1 靶值 0.24/SD0.02、水平2 靶值 2.40/SD0.20，两水平浓度差天然 ~2.1，远超 0.8 阈值 → 每对相邻水平都误触发 R-4s（实为高低浓度差，非波动）。

### 修复（`backend/app/services/qc_service.py`）
- `evaluate_r4s_project`：相邻对先各自按本水平靶值归一化为 z=(value-target_mean)/target_sd，再判 **|z_前 - z_后| > 4** 触发 R-4s。高低浓度被拉到同一尺度，只反映偏离各自靶值的程度。
- `aggregate_project`：构造 points 时额外传入 `mean`（用 `em`：靶均值或稳健均值），供归一化。
- 同天两水平都判失控(ooc)、跨天后点失控/前点警告(is_warning) 的判定规则不变。
- 同步更新模块文档 + 函数文档 + aggregate_project 文档。

### 验证
- `backend/scripts/test_westgard_r4s.py`：**11 用例全过**。新增用例10（甲肝浓度差不再误报）、用例11（用户示例：水平1 靶3/SD1 测5.5 z=+2.5，水平2 靶10/SD1 测7.5 z=-2.5，|Δz|=5>4 → 同天两水平都 R-4s 失控）。
- 部署：commit → push origin/main → `tcb cloudrun deploy`（正确喂参）→ `/_diag/build` 200 → `POST /qc-summaries/_recalc` 回填（updated/total）。
- 前端无需改（is_warning 黄色标签已就位）。

### 结论
用户确认定义：R-4s 指两质控点「分别和自己的靶值差」，归一化后差值>4 即判（如 2.5 与 -2.5 相加=5>4）。归一化实现与该定义一致。

### 部署坑复核（重要）
- 本次 deploy 后立刻 `/_diag/build` 返回 200，但前两次 `/_recalc` 仍跑到**旧 pod（旧逻辑）**，甲肝仍误报 R-4s。
- 原因：`/_diag/build` 返回 200 仅代表「有 pod 在跑」，流量切换（2-5min）完成前旧 pod 仍对外服务；该 build mark env 未随本次改动更新（仍 `scheduling-v3b-2026-07-25`），无法用 commit 区分。
- 正确做法：deploy 后**等流量切换完成**（轮询式地反复跑 `/_recalc` 直到数据反映新逻辑为止）。最终第 3 次轮询 `updated=85` 且甲肝 R-4s 全清，确认新代码已生效。
- 甲肝IgM 2026-06 现已全「在控」，验证通过。

## 排班：早班/连班独立状态行自动生成（已部署）

### 需求（用户口述工作流）
1. 工作流顺序：先批量录休息/质控 → 录夜班 → 录发热白班 → 排白班岗 → 生成早班/连班。
2. 早班/连班规则：每人**连上 2 天早班**再换人；连班同样每人连 2 天；**当天早班与连班不能是同一个人**。
3. 早班/连班在 Excel 中是独立两行（非白班岗位标记），故实现为独立无岗位状态行（post_id=None），与休息/质控并列。

### 实现（`backend/app/models/scheduling.py` + `backend/app/api/v1/scheduling.py`）
- 新增状态枚举 `ASSIGN_STATUS_EARLY="早班"` / `ASSIGN_STATUS_CONTINUOUS="连班"`，纳入 `STATUS_CATEGORIES` 与 `ASSIGN_STATUS_ALL`。
- 生成流水线（对齐用户规则）：
  - `early_seq[i] = roster[(i//2)%n]`（每人 2 天早班）；`cont_seq[i] = roster[((i-2)//2)%n]`（连班=早班整体后移 2 天 → 当天早班连班必不同人）。
  - 每个工作日为序列取人；若早班人当天 `busy`（非在岗/夜班）→ 顺延下一位；若连班人 `busy` 或撞早班人 → 顺延并保证 `c != e`。
  - 删除范围内「在岗」自动记录 + 旧早班/连班行后写入；保留手动非在岗记录。
  - **发热白班排除**：`fever_busy_by_date` 记录发热当天该人，union 进 `busy`，防止其当天再被排早班/连班。
- `/scheduling/grid` 已含 早班/连班 状态行（STATUS_CATEGORIES 顺序末尾）。

### 批量录入 UI 消歧（`frontend/src/views/scheduling/SchedulingList.vue`）
- 「每 N 天」「限星期」两字段仅对「发热门诊白班」类型（`spacing:true`）显示（其他类型隐藏），消除用户困惑。
- 新增 `batchTypeSpacing` computed；`BATCH_TYPES` 增加 发热门诊白班(spacing)/早班/连班 类型。
- 前端 `vite build` 通过；后端 `py_compile` 通过。

## 人员继教：新员工培训「编辑类别内容变空」根因修复（系统性）
- 用户反馈：新员工培训保存后点编辑非常卡顿，打开后培训类别/内容全空。
- 根因（比现象影响面更大）：`crud_base.make_router` 的 list/get/create/update 直接 `ReadSchema.model_validate(ORM对象)`，而 pydantic `from_attributes=True` 对 SQLAlchemy ORM 对象的 Text 列 JSON 字符串**不会触发 `mode="before"` 校验器的 `json.loads`**（实测 `model_validate(orm_obj).plan_items == []`，但同字符串 `json.loads` 正常；普通类对象 `model_validate` 正常）。→ 所有 `json_fields`（新员工培训 plan_items/detail_json、能力评估 scores_json 等 6+ 模块）读取时整列丢失，前端编辑取到空数组→卡顿/空白。
- 修复：`crud_base.py` 新增 `_json_default(f)`（按 schema 注解判 list→[]/dict→{}）、`_serialize(obj)`（ORM→dict 并手动 `json.loads` 字符串型 json_fields，空串/异常回退默认）、`_to_read(obj)`（`ReadSchema.model_validate(_serialize(obj))` 先转 dict 再校验，绕过 from_attributes 缺陷）；list/get/create/update 全部经 `_to_read` 返回并恢复 `response_model=ReadSchema`。对全部 `make_router(json_fields=...)` 模块一并生效。
- 部署：`_BUILD_MARK=new-emp-train-fix-json-read-2026-07-31`（commit `6ef9e38`，push origin/main + tcb deploy）。内网 curl `/api/v1/_diag/build` 第 ~5 分钟轮询才翻到新标记（CloudRun 容器构建+滚动发布慢，勿提前下结论）。
- **E2E 验证（Python urllib 端到端）**：admin 登录 → POST `/api/v1/education/new-employee-trains`（含 2 条 plan_items，中文内容 + method/exam_method 数组）→ 201 回显完整；GET / LIST 该记录 plan_items 仍为完整数组（非 `[]`）；DELETE 清理。**PASS** → 根因闭环。

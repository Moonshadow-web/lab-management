## 【经典坑】中文文件名下载 500：Content-Disposition 非 ASCII（订购管理导出失败）
- **现象**：`/reagent/orders/{id}/export-form` 三张订购单导出**全部 500**，前端只弹「导出失败」（`.catch(() => ElMessage.error('导出失败'))` 吞掉了原因）。
- **根因**：`reagent_management.py` 把中文文件名直接写进响应头：
  `headers={"Content-Disposition": f'attachment; filename="设备科订购表_{order.order_no}.xlsx"'}`。
  **HTTP 响应头只能 latin-1 编码**，Starlette `init_headers` 编码时抛
  `UnicodeEncodeError: 'latin-1' codec can't encode characters in position 22-27` → 500。
  本地复现方法：`StreamingResponse(...).init_headers({'Content-Disposition':'attachment; filename="中文.xlsx"'})`（需 starlette，无需 httpx/TestClient）。
- **修法（RFC 5987）**：`filename=` 只放 ASCII 回退，真实名用 `filename*=UTF-8''<urlencoded>`。
  新建公共工具 **`backend/app/core/http_utils.py::content_disposition(disposition, filename)`**（项目里 documents.py / cnas_standards.py 各有一份私有实现，reagent 这次漏用了）。
- **同类隐患一并修**：`comparison.py`（2 处）、`interlab.py`（2 处）附件下载用 `f'...filename="{a.original_name}"'`，original_name 是**用户上传的原始文件名**，中文必炸 → 全部改用 `content_disposition(disp, a.original_name)`。
  已确认安全的（勿重复改）：`change_log.py`、`education.py`（`filename*=UTF-8''`）、`documents.py`/`cnas_standards.py`（`_content_disposition`）、`eqa.py`、`qc_summaries.py`、`review.py`、`test_items.py`。
- **前端配套**：`ReagentOrders.vue::onExport` 改为 —— ①若返回体是 JSON blob 则解析 `detail` 抛错；②catch 里 `e.response.data instanceof Blob` 时读文本取 detail。**blob 响应下后端错误也以 blob 返回，不解析就永远只看到「导出失败」**。
- 验证：三张单全部 200，`Content-Disposition: attachment; filename="_2026080401.xlsx"; filename*=UTF-8''%E8%AE%BE...`；导出的 xlsx 38 行（表头+37 细项），材料编码/名称/规格/品牌/数量/单位/备注齐全。
- 部署 commit 59aaf7e，`_BUILD_MARK=http-content-disposition-utf8-filename-2026-09-05`。
- **通用排查思路**：下载类接口 500 先看响应头有没有非 ASCII；`responseType:'blob'` 的前端错误必须解析 blob 才能拿到真实原因。

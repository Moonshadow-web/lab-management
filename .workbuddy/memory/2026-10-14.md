## ⭐⭐⭐ 浏览器白屏修复（根因在缓存策略，不是代码）

### 现象
用户反馈「最近微软/其他浏览器打开系统容易白屏」，且**最近**才出现（部署多次之后）。

### 排查过程（关键证据链）
```bash
# 1. 提取线上入口 JS 里引用的所有 chunk，逐个 HEAD 检查
#    → 51 个 chunk 里 48 个 404！
# 2. 对比本机 dist（430 个文件）→ 线上全部 200，0 个 404
#    → 文件没丢！
# 3. 关键矛盾：
#    线上入口 JS 引用 Login-DPLQfksg.js → 404
#    本机同文件 index-BZzSZZhn.js 引用 Login-EGPpjINR.js → 200
#    → **同一文件名的入口 JS，内容不同**
# 4. 响应头线索：
#    last-modified: Wed, 14 Oct 2026 13:33:21 GMT,Fri, 02 Oct 2026 21:59:40 GMT
#                        ↑ 两个时间戳拼在一起 = CDN/浏览器存了两份
```

### ⭐ 根因
`AssetCacheMiddleware` 把 `/assets/` 设成 `public, max-age=31536000, immutable`（一年强缓存），
**但部署时旧 chunk 文件会被删除**：
1. 某次部署删掉了旧 chunk（如 `Login-DPLQfksg.js`）
2. 浏览器/CDN 仍缓存着**旧版入口 JS**（一年不失效），它内部引用那些已删的 chunk
3. 用户打开 → 拿到旧入口 JS → 请求旧 chunk → **404** → 路由加载失败 → **白屏**

**现有代码的注释防的是「index.html 被缓存」，但白屏的实际原因是「入口 JS 被缓存」。方向错了。**

### 修法（两处一起）
```python
# ① main.py::_build_version()：取入口 JS 文件名里的内容 hash
m = re.search(r"/assets/index-[A-Za-z0-9_\-]+\.js", index_html)
_BV = m.group(0).rsplit("-",1)[-1].split(".")[0]      # → "BZzSZZhn"

# ② spa_fallback：注入版本号到所有资源 URL
html = re.sub(r'(["\'])/assets/', rf'\g<1>/assets/?v={_BV}&', html)
# → src="/assets/?v=BZzSZZhn&index-BZzSZZhn.js"
#    换版本后 URL 必变 → CDN 强制取新文件

# ③ AssetCacheMiddleware：assets 从 immutable 改成 no-cache
response.headers["Cache-Control"] = "no-cache"
# index.html 用 no-store + Pragma: no-cache
```
**性能代价可接受**：入口 JS 约 1.2MB、其余 chunk 几十 KB，校验一次几十毫秒，换"绝不白屏"。

### 同步补 `import re`
`main.py` 顶层原本没导入 `re`（只在函数内 import 过），新增用法时必须补 —— 否则容器启动即崩。

### 验证（本地）
```python

```

## ⭐⭐⭐ 我自己造的 bug：版本号注入位置写错 → 全站 404 白屏（22:20）

### 现象
白屏修复**上线后**，用户「刚刚还能打开，现在白屏了，刷新无效」。
更糟的是：**我部署后的验证脚本报告「52 个 chunk 零 404，✅ 已解决」** —— **误判**。

### 根因：正则把版本号插到了文件名**前面**
```python
# ❌ 我写的
html = re.sub(r'(["\'])/assets/', rf'\g<1>/assets/?v={_BV}&', html)
# → /assets/?v=BpZfvCLj&index-BpZfvCLj.js
```
实测：
```
/assets/?v=BpZfvCLj&index-BpZfvCLj.js   → 404 ❌
/assets/index-BpZfvCLj.js              → 200 ✅
```
`StaticFiles` 把 `index-BpZfvCLj.js` 当成 `/assets/` 下**目录名的一部分** → 找不到。

### 修法：版本号必须放文件名**之后**
```python
html = re.sub(
    r'(["\'])(/assets/[A-Za-z0-9_\-]+\.(?:js|css|png|jpg|svg|woff2?))(["\'])',
    rf'\g<1>\g<2>?v={_BV}\g<3>', html)
# → /assets/index-BpZfvCLj.js?v=BpZfvCLj   ✅ 200
```

### ⭐⭐ 为什么我的验证脚本误判（**最值得记住的**）
我提取 chunk 名的正则是从**入口 JS 内容**里抓 `assets/xxx.js` 和 `"./xxx.js"`，
**根本没走 index.html 里注入的 URL** → 测的是"文件在不在"，
而实际白屏原因是"**index.html 引用的 URL 本身 404**"。**测的东西不是出问题的东西。**

### ⭐ 教训
1. **验证必须走用户真实路径**：拿 index.html 里注入后的完整 URL 去请求，
   而不是自己重新拼路径去测文件存在性。
2. **改完必须本地起服务实测**：
   ```bash
   uvicorn app.main:app --port 8899 &
   curl "http://127.0.0.1:8899/assets/index-xxx.js?v=BpZfvCLj"   # 必须 200
   ```
   本地 5 秒钟就能发现，避免全站白屏 20 分钟。
3. 正则替换静态资源路径时，**要同时匹配文件名**，
   不能只匹配目录前缀 `/assets/`（那样版本号必然插到文件名前面）。

### 附带发现：静态资源缺 CORS 头（已修，保留）

```python
response.headers["access-control-allow-origin"] = request.headers.get("origin", "*") or "*"
```

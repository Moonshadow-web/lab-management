# 2026-07-23 工作日志

## 上传仪器LIS数据 timeout 放宽（已部署）

### 现象
用户上传 `AU5800急.xls`（数据量大）报 `timeout of 15000ms exceeded`，前端 15s 硬性截断，
服务端尚未完成解析+聚合即被取消。

### 修复（`frontend/src/utils/request.js`）
- 主 axios 实例 `timeout: 15000 → 120000`（大文件上传+服务端解析留足 2 分钟）。
- 续期裸 axios 调用 `timeout: 15000 → 30000`（续期本身快，仅防弱网抖动）。
- `uploadQCSummary`（`frontend/src/api/qc.js`）用 `request.post` 且未单独覆盖 timeout，自动继承新默认。

### 说明
- 后端 `upload_qc_summary`（`backend/app/api/v1/qc_summaries.py:410`）为同步处理，无服务端超时；
  限制仅为客户端 15s。120s 对月度 LIS 导出（数万行）足够。
- 若以后出现超大量文件（>120s 解析），再考虑改为后台任务（BackgroundTasks）+ 轮询结果，
  当前暂不实现。
- Dockerfile 在部署期 `npm run build` 前端，改动随 push origin/main 后 `tcb cloudrun deploy` 生效。

### 部署
- commit → push origin/main → `tcb cloudrun deploy`（喂参：首提示回车选默认No自动切流量，次提示Y）。
- 待验证：deploy 后轮询至新 pod 生效，前端重新上传 `AU5800急.xls` 应不再超时。

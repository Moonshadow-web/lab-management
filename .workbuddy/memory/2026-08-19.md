## 性能验证解析修复（第二轮，2026-08-19 晚）

### 容器崩溃（Back-off restarting failed container）
- 根因：report_archives.py 里 debug 端点误用 `@custom_router.post`（custom_router 是 uncertainty.py 的变量，report_archives 里未定义）→ NameError → 容器启动失败。
- 教训：**改代码后必须用 venv python `import app.main` 冒烟**（沙箱默认 python 缺依赖，要用 `C:/Users/81526/.workbuddy/binaries/python/envs/default/Scripts/python.exe`）。
- 修：删除整个 debug 端点。

### 解析"验证内容空/内容不对"
- 根因链（多 bug 叠加）：
  1. ALB 模板"验证内容"在 C 列，ALP 在 B 列 → 固定读 B 列漏掉 content。
  2. R17 表头行（"验证要求/验证结果/验证结论"）被当数据行。
  3. content 兜底条件 `not content and not requirement` 太严，requirement 非空时走不到行号推导。
  4. sub 分配用固定行号（R17/R19），但 ALP/ALB 表头偏移不同。
  5. 正确度/实验室内CV 靠行号误判（R19 在 ALB 是实验室内CV，ALP 是正确度）。
- 最终方案：
  - 跨列扫描 B-I 找 content（含验证内容关键词）。
  - 跳过表头行（content/result/conclusion 是"验证要求/结果/结论"）。
  - content 兜底优先用 **requirement 关键词反推**（"实验室内CV"→精密度、"相对偏倚"→正确度），无 requirement 才用行号。
  - sub 按"出现顺序"分配（第1个 precision→precision1，不依赖行号）。
- 部署标记：vrf-crash-fix → vrf-seq-sub → vrf-req-priority（最终）。

## 性能验证解析修复（第三轮，2026-08-19 晚）

### 问题1：上传多出文件
- 根因：parse_and_store 内部创建 ReportArchive（original_name="{project}_性能验证_uploaded.xlsx"），upload_archive 端点又创建一份（original_name=用户原始文件名），导致一个文件→2 个归档
- 修：parse_and_store 不再创建 ReportArchive，文件由 upload_archive 统一处理
- 部署：vrf-linear-concl-2026-08-19

### 问题2：声称线性范围空
- 根因：vrf_parser 写死从 R9 B/D 列读 linear_low/high，但 ALB 模板 R9 是"低限 ≤ TEA"（不是声称范围），声称范围在 R21 F/G 列写"非线性临床可接受\n15-60"格式
- 修：智能 fallback——R9 没数字时从 R21 F/G 列正则提取数字

### 问题3：正确度验证结论空
- 根因：ALB 模板 R20 H 列是公式（[1]正确度-偏倚评估'!A32），data_only=True 时 None，导致 conclusion="" 被规范化后为空
- 修：_read_summary 循环里增加 conclusion 从 result 文本 fallback（"符合/通过"→"符合要求"；"不符合/不通过"→"不符合要求"）

### 问题4：合并区 cell 读取
- 根因：openpyxl 对 merged range 非左上 cell 返回 None，_val 之前直接返回空
- 修：_val 在 v=0 时查找 merged_cells.ranges，找到包含的 range 读左上 cell 的值
- 部署：vrf-merged-cell-2026-08-19

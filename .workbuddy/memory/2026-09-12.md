## 根因定位：attachment 头来自平台网关（2026-09-14 17:45 决定性证据）
- **决定性实验**：`/api/v1/__nonexistent__`（404）与 `POST /api/v1/auth/lab-groups`（405）——这两类响应由框架生成、**应用代码从不设置 Content-Disposition**，实测仍带 `content-disposition: attachment` → 证明该头**由 CloudBase Run 网关（响应头 `server: cbrgw`）统一添加**，与业务代码无关。
- 另：应用明确设 `inline` 的接口（cnas PDF 预览）线上仍为 `attachment` → 网关**覆盖**应用设置。
- 根因链：网关加 attachment → 大多数手机忽略该头照常渲染（20 人正常）→ 少数机型/微信版本严格遵守 → 弹"下载 html"。
- 排查用的对照方法（可复用）：①查 404/405 这类框架生成响应的头 → 判断是应用还是平台；②查与目标无关但代码里显式设相反值的接口 → 判断是否被覆盖。

## 排查：个别手机扫码变"下载 HTML"（2026-09-14 17:35）
- 现象：一位同事微信扫码答题时提示**下载 html**，其他人正常。

## 多专业组架构设计（方案文档 `docs/多专业组架构设计方案.md`）
- 需求：登录页选择专业组（生免/临检/微生物/分子/血库），非生免组仅部分模块且数据为空；用户管理/权限/审计仍仅 admin；**不得影响生免组现有功能**。方案文档：`docs/多专业组架构设计方案.md`。
- **已确认决策**：①一人一组（管理员可跨组）②其他 4 组初始为空、后续由用户提供数据批量导入 ③**编号含 KS 段（如 BG-KS-…、MHZYY-JYK-KS-…）= 科室共享**（SM=生免/LJ=临检/WSW=微生物/FZ=分子/XK=血库/KS=共享）④**其他组模块 = 工作台 + 项目查询 + 文件管理 + 仪器档案 + 试剂管理(目录/库存/盘库/月消耗/关联) + 到货接收**，其余菜单预留不显示。
- 技术方案：单库 + 行级隔离（业务表加 `group_code` 默认 'sm'）；登录带 group_code → JWT 带 active_group；**当前组为 sm 或空 → 后端不过滤（生免组零回归）**；其他组列表 = `group_code=当前组 OR 编号含 KS`。
- **风险清单（文档第六章，10 条）**：R1 批量加列致容器崩溃（分批+默认值+自愈幂等）｜R2 统一过滤误伤生免组（开关默认关、逐模块开、比对条数）｜R3 **唯一索引冲突**（`(group_code, code)` 复合唯一，最易引发插入失败）｜R4 存量回填 NULL｜R5 老令牌缺 active_group→默认 sm｜R6 公开链接与组归属（维修记录写仪器所属组）｜R7 配送角色跨组可见｜R8 部署命令与 include 行校验｜R9 导入必须带 --group｜R10 汇总只统计本组。含每阶段 Checklist（第七章）。
